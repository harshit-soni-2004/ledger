# 04 — API Contract (outline)

Base path: `/api/v1`. JSON over HTTPS. OpenAPI generated by springdoc and published at
`/swagger-ui.html` (local profile only).

## Conventions

| Concern | Rule |
|---|---|
| Authentication | `Authorization: Bearer <api_key>` ([ADR-0009](adr/0009-authentication.md)) |
| IDs | Prefixed public IDs only (`acct_…`); internal numeric IDs never exposed |
| Money | `{"value": "1500.00", "currency": "INR"}` — `value` is a **string**; numbers rejected |
| Timestamps | ISO-8601 UTC with microseconds: `2026-10-29T03:20:11.123456Z` |
| Dates | ISO-8601 `YYYY-MM-DD` |
| Idempotency | `Idempotency-Key` header **required** on all money-moving and resolution POSTs |
| Tracing | `X-Request-Id` and `X-Correlation-Id` accepted (validated, ≤ 64 chars) or generated; echoed in responses |
| Pagination | Keyset: `?limit=50&cursor=<opaque>`; response has `nextCursor` (null at end). Max `limit` 200 |
| Errors | RFC 9457 Problem Details + stable `code` |
| Unknown JSON fields | Rejected (400) on write endpoints to catch client typos |

**There is no endpoint that writes raw ledger entries.** Journals are created only by
domain operations (deposit, payout, transfer, reversal, ADMIN adjustment via resolution).

## Idempotency semantics

| Situation | Response |
|---|---|
| Header missing on a required endpoint | `400 IDEMPOTENCY_KEY_MISSING` |
| Header invalid (length/charset) | `400 IDEMPOTENCY_KEY_INVALID` |
| First request | Executes; response stored with the key in the same transaction |
| Same key, same normalized request, first committed | Stored status + body replayed; header `Idempotent-Replayed: true` |
| Same key, different normalized request | `422 IDEMPOTENCY_KEY_REUSED`; no side effects |
| Same key while first is still executing | Waits on the DB lock; then replay or execute. If wait exceeds ~5 s: `409 REQUEST_IN_PROGRESS` + `Retry-After: 1` |
| First failed with 5xx (rolled back) | Nothing stored; same key re-executes |
| Key older than retention (30 days) | Replay unavailable; for transfers, the permanent `(client, key)` unique index still prevents a duplicate and returns `409 IDEMPOTENCY_KEY_EXPIRED` |

Scope is per `(client, operation)`: the same key used for a transfer and for a reversal
does not collide.

Idempotency-Key: 0b8d4c4e-7a55-4d51-8f0f-2c3a9e1f6b10

### Transfer

```http
POST /api/v1/transfers
Authorization: Bearer sk_test_…
Idempotency-Key: 5b0e8c7e-4c1f-4a7e-9d0b-1f0a6c2d9e11
X-Correlation-Id: rent-flow-42

{ "sourceAccountId": "acct_01JBF3…", "destinationAccountId": "acct_01JBF4…",
  "amount": { "value": "1500.00", "currency": "INR" },
  "description": "October rent", "clientReference": "rent-2026-10" }
```

```http
201 Created
{ "id": "trf_01JBF5…", "status": "POSTED", "journalTransactionId": "jtx_01JBF5…",
  "sourceAccountId": "acct_01JBF3…", "destinationAccountId": "acct_01JBF4…",
  "amount": { "value": "1500.00", "currency": "INR" },
  "clientReference": "rent-2026-10", "createdAt": "2026-10-29T03:24:59.812345Z" }
```

Business rejection (committed and replayable):

```http
422 Unprocessable Entity
Content-Type: application/problem+json

{ "type": "https://ledger.local/problems/insufficient-funds",
  "title": "Insufficient funds", "status": 422, "code": "INSUFFICIENT_FUNDS",
  "detail": "Source account balance is insufficient for this transfer.",
  "transferId": "trf_01JBF6…", "requestId": "req_01JBF6…" }
```

Validation rules:

- `sourceAccountId ≠ destinationAccountId`; both exist and are `ACTIVE`.
- Caller owns the source account.
- `amount.currency` equals both account currencies (else `422 CURRENCY_MISMATCH`).
- `amount.value` > 0, scale ≤ currency minor units, ≤ configured max single amount.
- `description` ≤ 255 chars; `clientReference` ≤ 64 chars, `[A-Za-z0-9._:-]`.

As implemented (Phase 5):

| Check | When | Response | Recorded? |
|---|---|---|---|
| Source unknown or not owned by the caller | before the transaction | `422 ACCOUNT_NOT_FOUND` | No |
| Destination unknown or a system account | before | `422 ACCOUNT_NOT_FOUND` | No |
| Source = destination; malformed amount or `clientReference` | before | `400 VALIDATION_FAILED` | No |
| An account is not a LIABILITY wallet | before | `422 TRANSFER_NOT_ALLOWED` | No |
| Amount currency ≠ either account currency | before | `422 CURRENCY_MISMATCH` | No |
| Source would fall below its floor | under the balance locks | `422 INSUFFICIENT_FUNDS` + `transferId` | Yes, `REJECTED`, replayed for the key |
| Source or destination not `ACTIVE` | under the balance locks | `422 ACCOUNT_NOT_ACTIVE` + `transferId` | Yes, `REJECTED`, replayed for the key |

There is no configured maximum single amount yet; amounts are bounded by `DECIMAL(19,4)`.
The journal's `externalReference` is the `clientReference`. Lock conflicts are retried up to
three times; after that the answer is `503 RESOURCE_BUSY` with `Retry-After: 1` (planned name
`CONTENTION_RETRY_EXHAUSTED`), and nothing is recorded.

### Reversal

```http
POST /api/v1/journal-transactions/jtx_01JBF5…/reversals
Idempotency-Key: 9f1c…
{ "reason": "Customer disputed duplicate rent payment (ticket SUP-1042)" }
```

```http
201 Created
{ "reversalJournalId": "jtx_01JBF9…", "reversesJournalId": "jtx_01JBF5…",
  "transferId": "trf_01JBF5…", "transferStatus": "REVERSED" }
```

Errors: `409 ALREADY_REVERSED`, `422 CANNOT_REVERSE_REVERSAL`,
`422 INSUFFICIENT_FUNDS` (destination already spent the funds; no override in the MVP).

### Statement upload

```http
POST /api/v1/bank-accounts/bnk_01JB…/statement-imports
Content-Type: multipart/form-data; boundary=…
  file=@hdfc-2026-10.csv
  mappingProfile=default-v1
```

```http
201 Created
{ "id": "imp_01JBG…", "status": "COMPLETED_WITH_ERRORS",
  "totalRows": 120, "validRows": 116, "invalidRows": 2, "duplicateRows": 2,
  "balanceCheck": "PASSED", "periodStart": "2026-10-01", "periodEnd": "2026-10-31" }
```

Duplicate file: `409 DUPLICATE_IMPORT` with `existingImportId`. File-level failure
(missing required headers, wrong encoding, too large): `422 STATEMENT_REJECTED` and the
batch is stored with status `REJECTED` for auditability (except > 10 MB, rejected with
`413` before storage).

## Error code catalogue

| HTTP | Code | Meaning | Retry? |
|---|---|---|---|
| 400 | `VALIDATION_FAILED` | Field-level errors in `errors[]` | No (fix request) |
| 400 | `AMOUNT_PRECISION_EXCEEDED` | More decimals than currency allows | No |
| 400 | `IDEMPOTENCY_KEY_MISSING` / `IDEMPOTENCY_KEY_INVALID` | Header problem | No |
| 401 | `UNAUTHENTICATED` | Missing/invalid API key | No |
| 403 | `FORBIDDEN` | Role or ownership check failed | No |
| 404 | `NOT_FOUND` | Resource absent or not visible to caller | No |
| 409 | `ALREADY_REVERSED` | Journal already has a reversal | No |
| 409 | `DUPLICATE_IMPORT` | Same file already imported for this bank account | No |
| 409 | `RUN_ALREADY_ACTIVE` | A run is in progress for this bank account | Later |
| 409 | `REQUEST_IN_PROGRESS` | Same idempotency key still executing | Yes, same key |
| 409 | `IDEMPOTENCY_KEY_EXPIRED` | Key used beyond retention | No |
| 409 | `ALREADY_RESOLVED` | Subject already has a resolution | No |
| 413 | `PAYLOAD_TOO_LARGE` | File > 10 MB | No |
| 422 | `INSUFFICIENT_FUNDS` | Floor would be breached | New key after funding |
| 422 | `CURRENCY_MISMATCH` | Account/amount currencies differ | No |
| 422 | `TRANSFER_NOT_ALLOWED` | Transfer involves a non-wallet account | No |
| 422 | `ACCOUNT_NOT_ACTIVE` | Frozen or closed account | No |
| 422 | `IDEMPOTENCY_KEY_REUSED` | Same key, different request | No |
| 422 | `CANNOT_REVERSE_REVERSAL` | Reversal of a reversal | No |
| 422 | `STATEMENT_REJECTED` | File-level validation failure | No |
| 422 | `RESOLUTION_NOT_ALLOWED` | Action not valid for item category | No |
| 503 | `CONTENTION_RETRY_EXHAUSTED` | Deadlock/lock retries exhausted (implemented as `RESOURCE_BUSY`) | Yes, same key |
| 500 | `INTERNAL_ERROR` | Unexpected; no internals leaked | Yes, same key |
